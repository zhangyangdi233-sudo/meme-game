# Every UI tells the host through one event bus

Status: accepted

Any UI that reports a player action uses the game event bus. The host listens in one place. The main menu is the first caller (`start_game`, `continue_game`, `exit_game`, `language_picker`). Every other UI surface moves onto that same bus: fixed screens and controls whose count is known only at runtime.

The event carries the answer when the action has one: locale, ending choice, post, author, token, drag payload, volume, allow or skip, and the same kind of value.

## Event shape

`intent_emitted(intent_name: String, payload: Dictionary)`. A screen calls `emit_intent(intent_name, payload = {})`. An action without an answer sends an empty payload, so the main menu's calls did not change.

Intent names and each one's payload keys live in `UiIntents` under `scripts/` (Game side; Framework does not know it), beside `PropertyKeys` and `ServiceKeys`. One constant per intent, with its payload written in the comment, and one constant per payload key, for example `LANGUAGE_SELECTED` → `{KEY_LOCALE: String}`. The host and screens use the constants, not bare strings.

The host creates the bus and binds it in the service registry under `ServiceKeys.UI_EVENT_BUS` (ADR 0008). Binding twice is an error; tests clear the registry. A control built at runtime (a language choice, a post card, a tile) resolves the bus itself and emits; the host does not hand it down. A fixed layout scene still lists `BUTTON_INTENTS`.

The host is the only listener. It listens while it is in the tree and stops when it leaves; a later host in the same process reuses the bound bus. Its handler takes the answer and writes the model (ADR 0008); the screen does not.

The host may hand one domain's intents to an intent handler and still be the only listener. The social feed is the first: `SocialIntentHandler` claims the social intents, changes the state and the language material, writes its feedback line, and returns an `IntentResult` naming what the host presents (re-theme the page, close the window, settle an action, a pickup or a submit). The handler subscribes to nothing; the host routes to it and presents the result. Tracker: #83.

The notebook, the doctor sentence composer and the settings window followed (#84). Every handler extends the `@abstract` `IntentHandler` (`handles` / `handle`); the host keeps an ordered list and hands an intent to the first handler that claims it, after pointing every handler at the current run. `IntentResult` keeps only the kinds every domain shares (nothing, a spending action, a submit); a domain's own presentation kinds are constants on its handler, so a new domain touches its handler and the host's presentation match, not the shared type. Handlers and `LanguageMaterial` write the feedback line through one helper, `GameModels`. The meme the fusion slots take is the `selected_meme` model (not saved), written by the handlers and cleared by the host when a run starts or a day settles. Saving, the VHS overlay, the settings and history windows, the main menu and quitting stay the host's to present; the settings panel keeps owning `settings_open`. The host configures only the handler about to handle an intent, so a settings or doctor intent never builds the language material. The language picker (`LANGUAGE_SELECTED`), the main menu, the phone launcher, camera consent, the prologue, the ending screen and the reality conversation are still matched in the host.

Buttons that only hide or fold their own window (language "back", quit "return", doll-guide collapse) are UI too. They emit on this bus instead of a private signal or a direct call. Day transition, flashback, and action spend have no player control; when one is added, it uses this bus. That they happened travels on the bus as a game event (see below).

**Already on the bus:** the main menu, the language picker's choice (`LANGUAGE_SELECTED`), the phone launcher (app icons, phone close, app window close), camera consent (allow / skip, chosen source), the phone-camera connection overlay (retry, continue, disable), the settings window (volume, autoplay, VHS, language option, save, return to menu, exit request and confirm, history toggle), the HUD settings button, prologue finished, and the ending screen (language choice, restart). The social feed also raises everything on the bus: channel tabs, page changes, cards, likes, follows, close, the publish confirm, pickup units, and the composer drops, taps and submit. The publish page (composer, last result, confirm) is its own panel, `SocialPublishPanel`; the social shell hands it the page host and it raises the same intents. The notebook does the same: craft, fusion, tab changes, the resting canvas positions (committed once, never per frame), tiles dropped off the canvas or tapped, and the fusion slots. The panel still repaints its own page, channel and open post first; the host hears the intent to re-theme or to act. The reality conversation does the same: choice hover, unhover and press, and the continue button. The panel keeps the hovered choice and its preview itself. The doctor sentence composer raises token press, token drop, slot press and confirm; the token picked so far is the `selected_language_token` model (not saved), written by the doctor sentence handler, cleared by it when the sentence is spoken and by the host when the interaction ends. Hover and unhover only tell the host what the panel has already painted. The settings language option reuses `LANGUAGE_SELECTED`; the host sends it to the in-run handler during a run and to the picker handler otherwise. A runtime-built control raises with `GameEventBus.raise(intent, payload)`, which resolves the bound bus.

**Now every panel that reports a player action is on the bus.** No such panel keeps a private signal to the host. The social panel's drag handles no longer travel on a signal either: it registers them with the window manager it resolves from the service registry (#87). Whether settings is open is the `settings_open` model: the panel writes it and shows or hides its window, and the host registers on the same model to re-evaluate the chrome. The language picker's "back" and the quit "return" only close their own window and never had a private signal.

Signals and callbacks that remain are not a player action reaching the host:

- Low-level control signals inside one component (drag and drop, tile moves, radial selection, edge drawer expansion).
- A Dialog button's callback (#91). The caller hands the Dialog its own private callback in the spec; the press runs it after the Dialog closes. It is the caller talking to itself, not a player action reaching the host. When the answer needs the host, the callback raises the intent or game event on the bus itself (for example `GameEventBus.raise_event(...)`), so the host still hears it in one place.
- Game-side collaborators that are not panels: the Reality scene adapter (`nearby_targets_changed`; the cover watcher is a game event now, see below), the camera session (`tracking_ui_changed`), and `LanguagePresenter` (the notebook-home request; pickup and submit return an Action outcome and write the feedback text model). Its press sound is a game event now (see below). It raises no redraw request: the phone screens watch the free sentence and notebook models, and the guide and playtest windows watch the tutorial progress (ADR 0008). Tracker: #74.

## Game events on the same bus

Amended: the bus also carries game events, not only player actions. A game event is something that happened once and that several unrelated collaborators react to: the day settled, a cover watcher appeared or vanished, the flashback finished, a sound cue was asked for. The `GameEventBus` signal already allows many listeners; only the rule above kept the host the sole one.

- **Intents keep one listener.** A player action still reaches only the host, whose handler writes the model. Nobody else listens for an intent name.
- **Game events may have many listeners.** The sender does not know who listens. Audio, the Reality scene adapter and the desk log subscribe on their own instead of the host calling each one in turn.
- **State stays in models.** An event says that something happened. A fact that something is true now (tracking status, nearby targets, pollution) is a model (ADR 0008). One fact never gets both an event and a model.
- **Names.** Game event names and their payload keys live in `GameEvents` under `scripts/`, beside `UiIntents`, in the same shape: one constant per event with its payload in the comment.
- **Subscribing.** A listener subscribes by event name instead of matching every intent. It subscribes while it is in the tree, or from the moment the host attaches it, and unsubscribes when it leaves, the same lifecycle as the host's listener.
- **API.** `subscribe(event_name, listener)` / `unsubscribe(event_name, listener)`; the listener takes the payload. A sender with no bus in hand calls `GameEventBus.raise_event(event_name, payload)`, which resolves the bound bus. Events never go through `intent_emitted`, so subscribing adds no intent listener.
- **First user: sound cues (#86).** `SFX_REQUESTED {KEY_CUE}` asks for a short UI sound (`CUE_PICKUP_PRESS`, `CUE_PICKUP_LAND`, `CUE_NOTEBOOK_HINGE`). `GameAudioController` subscribes while it is in the tree and restarts the cue's player, so a repeat never stacks. `LanguagePresenter` raises the press cue on a successful pickup and the host raises land and hinge when the glyph lands; neither holds an `AudioStreamPlayer`.
- **Cover watcher (#88).** The floor generator raises `COVER_WATCHER_APPEARED {KEY_FLOOR}` when the figure steps into view and `COVER_WATCHER_VANISHED {KEY_FLOOR}` when it has withdrawn; nothing forwards them. `GameAudioController` subscribes to the appearance and plays the stinger, which is left to finish after the figure withdraws. `CoverWatcherSightings` subscribes to both from the moment the host attaches it: the appearance marks the floor seen in the current run, the withdrawal records its line in the event log. The host only attaches it, detaches it when it leaves the tree, and points it at each new run; it connects no watcher signal and keeps no watcher handler.
- **Day settlement (#89).** The host settles a pending day and raises `DAY_SETTLED {KEY_DAY, KEY_FROM_FLASHBACK}` once per settlement; it no longer calls the adapter, audio or the desk line in turn. The Reality scene adapter subscribes while it is in the tree and ends any conversation and forgets the nearby targets. `GameAudioController` subscribes while it is in the tree and re-syncs the mix from the inputs the host hands it once (`set_state_source`), deferred to the end of the frame so it reads the street after the adapter (and any other listener) has reacted, whatever the subscription order. `DaySettlementFeedback` subscribes from the moment the host attaches it (same lifecycle as `CoverWatcherSightings`): it clears the `selected_meme` model and shows the latest event log line. In a beat the day transition already settled the day, so the flashback's finish is its own happening. `DaySettlementFeedback` writes the "already the next day" line for it, and for a day the flashback itself settled (`KEY_FROM_FLASHBACK`); the finish may reach it before that settlement, so whichever comes last writes the new day's line. The host still presents what follows a settlement: the ending, or the redrawn play surfaces.
- **Flashback finished (#90).** The pollution flashback director raises `FLASHBACK_FINISHED` when its timeline ends; the flashback overlay takes no callback. The narrative director subscribes while it is in the tree: when the beat is on its flashback it closes the overlay and its audio, asks the host to settle (which raises `DAY_SETTLED` with `KEY_FROM_FLASHBACK`), and moves the beat on. A finish with no flashback on screen settles nothing. Tests skip the timeline by raising the event themselves.
- **Still not events:** signals inside one component (drag and drop, tile moves) and getters polled every frame (flight targets).

Opening and closing via the screen manager (create once, hide, reuse) serves the main menu and the Dialog (#91). This decision is only the interface UI uses to notify the host. Tracker: #43.
