### 單字污染的規則（依上表整理）

- 投稿**成功成為世界規則**時，句子裡用到的字才會被污染。
- 污染以「撿到的單位」計算：中文一個字，日文、英文一個詞。
- 被污染的字顯示成紅色亂碼，不能恢復，但仍可放進句子。
- 投稿時計算句子裡被污染單位的比例，**超過門檻（暫定 50%）就判定為「被讀錯」**，規則不生效。
- 發布前在組句區顯示亂碼比例或警告，讓玩家知道風險。

> 第一點和最後三點是程式端依企劃方向補上的細節，企劃尚未逐條確認。門檻數值之後可依試玩調整。

實作票：[#117](https://github.com/zhangyangdi233-sudo/meme-game/issues/117)

## 2. 企劃主動補充的現況

- 第一章已做成類似小島秀夫《P.T.》的形式：玩家要在地下室重複繞 5 圈，每一圈有一位 NPC，可以選擇幫助他。
- 目前每一圈都必須**發布一次並和 NPC 對話一次**，才能進入下一圈。**企劃表示這個條件之後可能要改。**
- 第一章與第二章的玩法已用 codex 修改，放在企劃分支上。

## 4. 程式端的搬移決策（供企劃知悉）

以下由程式端決定，不需要企劃回答，但會影響企劃的工作方式：

- **企劃分支不直接合併。** 它是從 8 月 18 日的舊版本分出來的，和 `dev` 已經差了 238 個 commit。程式端會把裡面的功能一塊一塊重新接到 `dev` 上，企劃分支只當作行為參考。
- **搬移期間，請不要再往企劃分支加新功能。** 第一批功能搬進 `dev` 之後，請改從 `dev` 開分支繼續做。
- **大型資源（`.blend`、`.glb`、影片、第一章貼圖）改用 Git LFS 存放。** 程式端已在 `dev` 設定好規則。
- **舊存檔不相容。** 遊戲尚未發行，搬移時直接提高存檔版本號，讀到舊存檔就開新局。
- **搬移期間遊戲可能暫時玩不完整**，但每一步都能啟動，測試全綠。

搬移的實作票：[#108](https://github.com/zhangyangdi233-sudo/meme-game/issues/108)～[#117](https://github.com/zhangyangdi233-sudo/meme-game/issues/117)。
